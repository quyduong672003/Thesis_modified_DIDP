1\. The Basic Idea 

It is to create a Python-friendly wrapper for an existing, generic CABS algorithm. Its main job is to act as a "Project Manager" that does three things when a user in Python calls m\_dp.CustomDualBoundCABSv1(...):

* Accept Inputs: It interprets the model and your new Python dual bound function as separate arguments.
* Prepare the "Work Plan": It calls create\_combined\_evaluator\_with\_py\_func helper. This helper creates a new Rust function (a "closure") that combines the model's Rust bounds with the Python function into a single heuristic (h\_evaluator).
* Hire the "Worker": It passes this new, combined h\_evaluator (along with standard helpers for cost) to the real CABS algorithm, create\_user\_priority\_cabs, which does all the heavy lifting.



2\. The Key Functions Involved

* Functions in this file:

new(...): This is the constructor (the \_\_init\_\_ in Python). This is where 99% of the logic happens.



search(...) / search\_next(...): These are simple passthrough functions. They just tell the real CABS solver (which is wrapped inside self.0) to "run".



* Functions called by this file:

create\_combined\_evaluator\_with\_py\_func(...) (from your customized\_evaluator.rs): It's the helper you wrote that creates the combined Rust+Python heuristic function.



create\_user\_priority\_cabs(...) (from dypdl\_heuristic\_search): This is the real CABS algorithm. It's a generic, high-performance solver that accepts any heuristic function you give it.



create\_default\_g\_evaluator\_vectors(...) (from user\_priority\_evaluator.rs): This is a standard helper from the original library. It's used to get the functions that calculate the "cost-so-far" (the g-value) for each transition.

// --- Type Alias for our Heuristic Function ---



// We define a "type alias" named `HBuilder` to make our code cleaner.

// It's just a nickname for a very complex type.

//

// This type is `Box<dyn Fn(\&StateInRegistry) -> Option<OrderedContinuous>>`:

//

// \* `Box<...>`: This means the function will be stored on the heap. This is

//   necessary for \*\*type erasure\*\*.

//

//   \*\*Why?\*\* The `if float\_cost { ... }` block and the `else { ... }` block

//   in your `new()` function create two \*different concrete types\* (one 

//   for `<Integer>`, one for `<OrderedContinuous>`). A variable

//   (like `h\_evaluator`) can only have one concrete type.

//

//   `Box` (storing on the heap) combined with `dyn Fn` (a "dynamic" trait)

//   "erases" the specific type, allowing you to store either function in

//   the `h\_evaluator` variable as long as they have the same function signature.

//

// \* `dyn Fn(...)`: This is the "dynamic trait object" part that enables

//   the type erasure. It means "a variable that can hold \*any\* function

//   (or closure) that matches this signature."

//

// \* `\&StateInRegistry`: This is the function's input. It takes a reference

//   to a `StateInRegistry` object, which is the struct the search

//   algorithm uses to represent a state.

//

// \* `-> Option<OrderedContinuous>`: This is the function's output. It \*must\*

//   return a sortable float (or None).

//

// \* `OrderedContinuous`: This is the \*\*sortable float\*\*. Standard Rust

//   floats (`f64`) are not "sortable" because of the existence of

//   `NaN` (Not a Number), which breaks sorting rules.

//   `OrderedContinuous` is a wrapper around `f64` that provides a

//   total ordering, making it safe to use in the priority queues that

//   CABS relies on.

//

type HBuilder = Box<dyn Fn(\&StateInRegistry) -> Option<OrderedContinuous>>;

\#\[pyclass(unsendable, name = "CustomDualBoundCABSv1")]

pub struct CustomDualBoundCabsPy(

&nbsp;   //

&nbsp;   // `WrappedSolver`: This is the \*\*wrapper\*\* you asked about.

&nbsp;   //

&nbsp;   // \*\*Problem:\*\* The CABS algorithm in Rust is generic. It can be

&nbsp;   // `Cabs<Integer>` or `Cabs<OrderedContinuous>`. Python doesn't

&nbsp;   // understand these generics.

&nbsp;   //

&nbsp;   // \*\*Solution:\*\* `WrappedSolver` is an `enum` (a type that can be one

&nbsp;   // of several variants) that holds the \*actual\* solver inside.

&nbsp;   // It looks something like this:

&nbsp;   //

&nbsp;   // enum WrappedSolver<I, F> {

&nbsp;   //     Int(I),

&nbsp;   //     Float(F),

&nbsp;   // }

&nbsp;   //

&nbsp;   // In our `new()` function, we check the model's cost type and put either

&nbsp;   // the Integer solver or the Float solver \*inside\* this wrapper.

&nbsp;   //

&nbsp;   // When you call `solver.search()` from Python, the `WrappedSolver`

&nbsp;   // internally matches on which variant it is and calls `search()`

&nbsp;   // on the \*real\* solver it's holding.

&nbsp;   //

&nbsp;   // `Box<dyn Search<...>>`: This just says "it holds \*any\* solver

&nbsp;   // that implements the `Search` trait for `Integer` or `OrderedContinuous`."

&nbsp;   //

&nbsp;   WrappedSolver<Box<dyn Search<Integer>>, Box<dyn Search<OrderedContinuous>>>,

);

&nbsp;       f\_operator: FOperator,

&nbsp;       time\_limit: Option<f64>,

&nbsp;       quiet: bool,

&nbsp;       initial\_beam\_size: usize,

&nbsp;       max\_beam\_size: Option<usize>,

&nbsp;       expansion\_limit: Option<usize>,

&nbsp;       // Standard setup: print version, get F-operator, check cost type,

&nbsp;       // and get a reference-counted pointer to the inner Rust model.

&nbsp;           println!(

&nbsp;               "Solver: CustomDualBoundCABSv1 from DIDPPy v{}",

&nbsp;               env!("CARGO\_PKG\_VERSION")

&nbsp;           );

&nbsp;       }



&nbsp;       let bound\_evaluator\_type = FEvaluatorType::from(f\_operator.clone());

&nbsp;       let f\_evaluator\_type = FEvaluatorType::from(f\_operator);

&nbsp;       let float\_cost = model.float\_cost();

&nbsp;       let rust\_model = Rc::new(model.inner\_as\_ref().clone());

&nbsp;       // "cost-so-far" (g-value) functions for each transition.

&nbsp;           create\_default\_g\_evaluator\_vectors(\&rust\_model);



&nbsp;       // --- 3. Create the Custom `h` Evaluator (The "Magic") ---

&nbsp;       // This is the fix for the `if/else` type mismatch error.

&nbsp;       // We declare `h\_evaluator` to have the single, concrete type `HBuilder`.

&nbsp;       let h\_evaluator: HBuilder = if float\_cost {

&nbsp;           // If the model uses Floats, we call our helper specifying OrderedContinuous

&nbsp;           Box::new(create\_combined\_evaluator\_with\_py\_func::<OrderedContinuous>(

&nbsp;               rust\_model.clone(),

&nbsp;               dual\_bound\_func,

&nbsp;           ))

&nbsp;           Box::new(create\_combined\_evaluator\_with\_py\_func::<Integer>(

&nbsp;               rust\_model.clone(),

&nbsp;               dual\_bound\_func,

&nbsp;           ))

&nbsp;       }; // `Box::new()` "erases" the type, solving the compiler error.



&nbsp;       // --- 4. Package Evaluators ---

&nbsp;       // The real CABS solver wants all functions in one struct.

&nbsp;       // We package our default `g` functions and our new custom `h` function.

&nbsp;       let user\_evaluators = UserEvaluators {

&nbsp;           forced\_g\_evaluators,

&nbsp;           g\_evaluators,

&nbsp;           h\_evaluator, // Pass our combined Rust+Python heuristic

&nbsp;           f\_evaluator\_type,

&nbsp;       };



&nbsp;       // --- 5. Create the Real Solver ---

&nbsp;       // This block is boilerplate. It sets up the parameters (like time limit)

&nbsp;       // and then calls `create\_user\_priority\_cabs` with our `user\_evaluators`.

&nbsp;       // The only difference is the <Type> (Integer vs OrderedContinuous).

&nbsp;       if float\_cost {

&nbsp;           let primal\_bound = if let Some(primal\_bound) = primal\_bound {

&nbsp;               Some(OrderedContinuous::from(

&nbsp;                   primal\_bound.extract::<Continuous>()?,

&nbsp;               ))

&nbsp;           } else {

&nbsp;               None

&nbsp;           };

&nbsp;               max\_beam\_size,

&nbsp;               beam\_search\_parameters: BeamSearchParameters {

&nbsp;                   beam\_size: initial\_beam\_size,

&nbsp;                   keep\_all\_layers,

&nbsp;                   parameters: Parameters::<OrderedContinuous> {

&nbsp;                       primal\_bound,

&nbsp;                       time\_limit,

&nbsp;                       get\_all\_solutions: false,

&nbsp;                       quiet,

&nbsp;                       initial\_registry\_capacity: None,

&nbsp;                       expansion\_limit,

&nbsp;                   },

&nbsp;               },

&nbsp;           };

&nbsp;           let solver = create\_user\_priority\_cabs(

&nbsp;               rust\_model,

&nbsp;               parameters,

&nbsp;               bound\_evaluator\_type,

&nbsp;               user\_evaluators,

&nbsp;           );



&nbsp;           // Return our Python wrapper class

&nbsp;           Ok(CustomDualBoundCabsPy(WrappedSolver::Float(solver)))

&nbsp;       } else {

&nbsp;           // Same logic, but for Integer

&nbsp;           let primal\_bound = if let Some(primal\_bound) = primal\_bound {

&nbsp;               Some(primal\_bound.extract::<Integer>()?)

&nbsp;           } else {

&nbsp;               None

&nbsp;           };

&nbsp;           let parameters = CabsParameters {

&nbsp;               max\_beam\_size,

&nbsp;               beam\_search\_parameters: BeamSearchParameters {

&nbsp;                   beam\_size: initial\_beam\_size,

&nbsp;                   keep\_all\_layers,

&nbsp;                   parameters: Parameters::<Integer> {

&nbsp;                       time\_limit,

&nbsp;                       get\_all\_solutions: false,

&nbsp;                       quiet,

&nbsp;                       initial\_registry\_capacity: None,

&nbsp;               },

&nbsp;               rust\_model,

&nbsp;               parameters,

&nbsp;               bound\_evaluator\_type,

&nbsp;               user\_evaluators,
